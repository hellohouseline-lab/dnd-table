## Notes for the next session
- Voice and cameras: `src/call/`. `vdoLinks.ts` builds the VDO.Ninja addresses (checked on 26 October: `&push`, `&view`, `&password`, `&videodevice`/`&audiodevice` by name with underscores for spaces, 0 for none, `&autostart&webcam&cleanoutput`, `&mute&videomute` to start off, `&videobitrate`, `&cover`, `&transparent`, `&noaudio`). The IFRAME API takes `{ mic }`, `{ camera }` and `{ volume }`, and sends `seeding-started` from the sender and `new-video-track-added`, `new-audio-track-added` and `end-view-connection` from a viewer. VDO.Ninja isn't pinned to a version; if it changes, `npm run test:call` is the check. `CallProvider.tsx` holds the call (`TableCallLayer` for real tables, `CallEngine` shared with the previews). Call previews without signing in: open `#/dev/call/dm/<any word>` and `#/dev/call/p1/<the same word>` (or `join`) in two windows.
- Browsers started by Playwright count a click from the start, so the "Click anywhere to hear everyone" step can only be seen in a normal browser.
- The project needs Node 24 (`.nvmrc`). Matt's Mac default is still Node 20, so run commands with Node 24 on the PATH (`~/.nvm/versions/node/v24.22.1/bin`).
- Local dev runs on port 5180: `npm run dev`, then open http://localhost:5180/dnd-table/.
- Pushing uses the GitHub CLI login for hellohouseline-lab (set in this repo's git config), because the Mac's saved git login is for another account.
- When a milestone merges, update `src/screens/progress/roadmap.ts` so the Build progress page shows the new status.
- Database: the Supabase CLI is logged in and linked. `npm run db:push` applies new files in `supabase/migrations/`, `npm run db:types` regenerates `src/live/database.types.ts`, and `npm run test:db` runs the pgTAP tests in `supabase/tests/database/` against the live project inside a transaction that is always undone (no Docker on this Mac, so `supabase test db` can't run).
- Supabase's advisor warns that signed-in users can call the security-definer functions and that the table rules apply to anonymous guests too. Both are on purpose: each function checks the caller, and guests can't join a table, so they see nothing (covered by tests). Leaked-password protection doesn't apply, as nobody uses passwords.
- Login uses the implicit flow (see the corrected note in `PHASE1_PLAN.md` section 1). A link opened on a different device, such as a phone, signs in that device, so the email also carries a code: after asking for a login, the "Check your email" step has a box for it. The email wording lives in `supabase/templates/` and must match the dashboard's Magic Link and Confirm signup templates.
- Design previews with made-up data, only under `npm run dev`: `#/dev/join/dm`, `#/dev/join/player`, `#/dev/join/new`, `#/dev/table`, `#/dev/table/asked` (the roll prompt), `#/dev/character`, `#/dev/check-email`, `#/dev/dm/party`, `#/dev/dm/log`, `#/dev/dm/asked` (the DM's results), `#/dev/dm/moments` (every kind of result card) and `#/dev/stage` (uploads stay in the tab; sound plays). In the DM preview, made-up players answer a request a moment after it's sent (`src/screens/dev/previewAsking.ts`).
- Sound: `src/audio/mixer.ts` wraps Howler (pinned at 2.2.4). Music and ambience stream (`html5: true`, so long tracks aren't decoded into memory); effects use Web Audio. Fades start on Howler's 'play' event, because a fade asked for while a streamed sound is still starting waits in Howler's queue for good. One tab per browser plays, chosen with the Web Locks API.
- Files: `src/live/files.ts` keeps art and sound in the browser's Cache Storage under made-up addresses, with object URLs for playing and showing them. Uploaded files get new names, so a kept copy is never stale.
- Playwright uses the Mac's own Chrome (`channel: 'chrome'`), so there is no browser download. It starts `npm run dev` itself, or reuses one already running on port 5180. It isn't part of the deploy workflow yet. In the previews dice are thrown in the browser, not by the server. Sample characters live in `src/screens/dev/sampleData.ts` and are reused by the render tests. Keep preview data inside functions, not built when a file loads, or the live build can't leave it out (check with `grep fumble dist/assets/*.js` after `npm run build`).
- Dice: the 3D library is wrapped in `src/dice/diceTray.ts`. It is pinned at 0.0.12 and patched in two places at run time (textures come from `src/dice/textures.ts`; each throw gets a fresh colour set name because the library shares texture settings between sets). Check both if the version ever changes. `natural` is a reserved word in Postgres, hence the column name `natural_d20`.
- To update the rules data, change the commit in `scripts/import-srd.ts`, run `node scripts/import-srd.ts`, and check `npm test`.
